# bpsc-cmo v0.1.0

## Shared foundation

Derived from the supplied latest Library Management System reference ZIP. Retains Fortify login, login throttling, password controls, inactive-account protection, session version invalidation, user CRUD, administrator protections, profile permissions, designation CRUD, unit CRUD and seeds, fixed roles/gates, and audited request/account/organization activity. Library catalog, circulation, acquisition/import, member registration and related routes, tables and views are excluded from this new starter. The inherited designations and units are retained exactly as seed data, including Librarian designations; these are organizational titles, not user roles.

Project: `bpsc-cmo`. Header: `BPSC CMO — Chairman Office`. English UI; Bangladesh timezone. New teal/amber palette and expert favicon. No real people, evaluations or default credentials are included. Create the first Administrator interactively.

## Current role matrix

| Capability | Administrator | Chairman | Member | Staff |
| --- | --- | --- | --- | --- |
| Public directory, own profile/password | Yes | Yes | Yes | Yes |
| Users, roles, designations, units, audit logs | Yes | No | No | No |
| Expert CRUD, active/public status | Yes | No | No | Yes |
| Questionnaire CRUD | Yes | No | No | No |
| Submit viva-day evaluations | No | Yes | Yes | No |
| Read evaluations | All | Own | Own | No |

This initial role mapping is implemented with server-side gates. Role definitions are fixed and the roles screen documents them; user role assignment is managed through Users. Each new module should add its own gates, controllers, models and routes while reusing the shared identity/audit foundation.

## Expert Evaluation module

- Two pools: Expert and Departmental Expert. Fields: name, pool type, designation, organization/department, specialization/subject, optional email/mobile/biography, active status and public publication flag.
- Backend expert search by name, organization and specialization; pool-type filter and pagination. Deletion uses soft deletion so past evaluations are retained.
- Read-only public directory and profile pages expose only active, explicitly published experts. Contact details and evaluation data stay internal. No public registration or submission routes are provided.
- Questions: add/edit/delete; Rating 1–5, Single Choice (2–10 unique options), Text; required/optional, active/inactive and display order. No sample questions are imposed; Administrator sets the questionnaire.
- Chairman/Member select an active expert, viva date and optional viva/board reference, complete the active questionnaire and confirm submission. Ratings use 1 as lowest and 5 as highest.
- Initial starter rule: one final evaluation per evaluator, expert and viva date, enforced with a database unique constraint. Viva dates can be today or earlier. These initial rules can be revised when the detailed board/session workflow is supplied.
- Submissions are immutable in the UI and have no update/delete route. The expert/evaluator identity and full questions/options/answers are snapshotted. Later edits or soft deletions do not rewrite previous submissions.
- A changed questionnaire causes an open form to be rejected on submission, requiring a reload. Server validation rejects unknown answers, invalid choice/rating values, missing required answers, inactive experts, future viva dates and duplicate submissions.
- Audit logs retain who/what/when/IP. Submission audit entries contain evaluation metadata, not answer text. Answers are accessible only through the authorized evaluation pages.

## Installation scope

Use the full ZIP in a new project directory and a fresh database. Do not paste over the library project or point this app at its database. Composer/npm lockfiles and compiled frontend assets are included; installed dependencies, `.env`, runtime data and caches are excluded.

## Next modules

The starter does not impose viva board scheduling/assignment, expert allocation, aggregate scoring, reporting/export or other office workflows. Their rules will follow later requirements.
