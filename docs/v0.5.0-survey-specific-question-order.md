# bpsc-cmo v0.5.0 — survey-specific question assignment and order

## Apply the update

Apply after v0.4.0. Back up the project, extract the Paste & Replace ZIP into the existing project root, then run:

```bash
php artisan optimize:clear
```

No new migration or dependency installation is required. Updated production frontend assets are included. Existing survey-question positions and all submitted answers remain intact. The fixed `readme.md` is unchanged and is not included in this patch.

## Workflow

1. Create or edit reusable question content and answer settings in **Question Bank**. The bank no longer exposes a global Order field, Order column or survey-assignment controls.
2. Open **Survey Create/Edit → Select & Arrange Questions**.
3. Search the available bank and select questions. Added questions append to the selected list.
4. Arrange selected questions by dragging their handle, using the Up/Down buttons or entering a numeric Order. Save the survey to persist both membership and sequence.

Selected questions and available bank questions are shown separately. Search filters only the available bank; it does not hide or deselect chosen questions. Without JavaScript, the checkboxes and numeric Order fields remain usable. Give selected questions distinct positive order numbers; lower numbers appear first. Omitted numeric orders append in submitted sequence.

## Scope and data preservation

- Each survey stores its own sequence in the existing `question_survey.position` association field.
- One question may appear first in one survey and last in another. Changing one survey has no effect on another survey's order.
- Editing shared question content/settings never changes its survey memberships or positions. Membership and order are now managed exclusively through Survey Create/Edit.
- Question Bank lists newest questions first. Survey details and attendance forms follow the saved survey order.
- Existing positions are not changed on deployment. When saving a survey, selected questions are normalized to consecutive positions while preserving their chosen order. Historical ties are displayed consistently by question ID.
- Updating survey metadata without sending question selections retains the existing sequence. Clearing all selections is allowed for a draft; activation still requires at least one active question.
- Duplicate order numbers, invalid positions and unavailable/deleted question IDs are rejected without partially changing assignments.
- A reordered questionnaire invalidates an already-open attendance form. Previously submitted responses retain their original question/answer order.
- The old `questions.sort_order` column is retained only for database compatibility. Current forms, ordering, fingerprints and audit field selection no longer use it. No database cleanup is required.
- Permissions are unchanged: Administrator and Staff manage surveys/questions; participants can attend their assigned surveys. Reordering is audited with before/after ordered question IDs.
