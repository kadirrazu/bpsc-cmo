# bpsc-cmo v0.4.0 — attendance experience and Member daily limit

## Apply the update

Apply this update after v0.3.0. Back up the project/database, extract the Paste & Replace ZIP into the existing `bpsc-cmo` project root, then run:

```bash
php artisan optimize:clear
php artisan migrate
```

Production frontend assets are included. No Composer/npm dependency updates are needed. The fixed `readme.md` is unchanged and is not included in the patch.

## Searchable expert selection

The attendance form now offers an authenticated server-backed Expert search. It searches active experts by name, organization, designation or specialization, with 20 results per request and a **Load more experts** action. Large pools do not load all experts into the page.

Type a search term, then click a result or use Arrow Up/Down and Enter. Escape dismisses results. Editing the search clears the previous expert ID, and typing an unmatched name cannot submit as a selection. Delayed results from earlier searches are ignored. The selected expert is retained after answer-validation errors, including selections outside the first result page.

The lookup endpoint requires an evaluator account and an active survey assigned to that role. It excludes inactive/soft-deleted experts and does not return contact fields. The final submission still revalidates the active expert. A limited native-select and server-search fallback is available when JavaScript is disabled.

## Question and answer layout

- Clear survey introduction, Evaluation Details and Questionnaire sections.
- Numbered question cards with separate hint panels and larger answer controls.
- Short text, Select, Date, Time and Checkbox questions use two columns on larger screens and one column on small screens. Long text and option/rating groups retain full-width space.
- Radio, rating and multiple-choice answers use clickable selection tiles with keyboard-focus and checked states.
- Required questions show a red star. Optional questions are explicitly labelled. A note below the questionnaire explains that red-star questions require answers and all others are optional.
- Time questions default to `10:00` (10:00 AM). Browser-native time formatting follows the user's locale; the form also displays the explicit default label. Existing/previously entered answers, including an intentionally cleared optional value, are preserved.

## Member Dashboard

A Member's common Dashboard now lists active, non-deleted surveys assigned to Member, with direct **Attend Survey** links. Surveys assigned only to Chairman, drafts, closed surveys and deleted surveys are excluded. The list is paginated when necessary, and an empty state appears when none are available.

## Once per expert per viva date

A Member may submit only one evaluation for a given expert and viva date **across all surveys**. Switching surveys cannot bypass this limit. Another Member, another expert or another viva date is a separate combination.

The existing Chairman workflow retains its earlier per-survey duplicate rule. This release changes the daily rule specifically for Member, as requested.

The Member check and a database-backed unique `(user_id, expert_id, viva_date)` reservation run inside the submission transaction. Validation failures do not reserve a day. A competing duplicate reservation produces the normal validation message instead of adding another response.

The migration backfills existing evaluator/expert/date combinations. Historical submissions, including duplicates that earlier versions allowed across surveys, are retained exactly; no historical response is deleted or rewritten. Existing combinations prevent a new Member submission for that expert/date.
