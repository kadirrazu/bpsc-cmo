# bpsc-cmo v0.5.4 — Expert profile, reports and removal permissions

## Apply

Apply after v0.5.3. Extract the Paste & Replace ZIP into the existing project root and run:

```bash
php artisan optimize:clear
```

No new migration, dependency update or frontend rebuild is required. The fixed `readme.md` is unchanged.

## Expert profile

The **Remove from pool** card is now the last content section, after Evaluation History & Summary. Only Administrator sees the card or can submit an expert DELETE request. The endpoint and controller both enforce removal authorization. Existing evaluation records are retained when an expert is removed.

Administrator and Chairman can view **Evaluation History & Summary**, filtered expert reports and report CSV exports. The reports' View Answers links also allow Chairman to read the corresponding submitted answer details, including other evaluators' responses. Chairman cannot create, edit or remove expert profiles.

Staff can continue creating/editing experts and viewing basic profiles, but cannot see evaluation history, report links or the removal card. Member retains attendance and own-response access; direct Expert Pool/profile and report routes remain restricted.

## Access matrix

| Capability | Administrator | Chairman | Staff | Member |
| --- | --- | --- | --- | --- |
| Expert Pool/profile viewing | Yes | Yes | Yes | No |
| Expert creation/editing | Yes | No | Yes | No |
| Remove from pool | Yes | No | No | No |
| Expert evaluation history/summary | Yes | Yes | No | No |
| Expert reports and report exports | Yes | Yes | No | No |
| Report answer details | Yes | Yes | No | Own response only |
| System management and audit logs | Yes | No | No | No |

Chairman's own Responses list remains scoped to their submissions; the expert-report workflow supplies cross-evaluator history. Survey/question authoring permissions and attendance rules are unchanged. Menus and action links follow these gates, and direct requests are checked independently of visibility.
