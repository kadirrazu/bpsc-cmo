# bpsc-cmo v0.3.0 — Question Bank, rating settings and expert reports

## Installation

Apply after the v0.2.0 module/survey update. Back up the project and database, extract the Paste & Replace ZIP into the existing `bpsc-cmo` project root, then run:

```bash
php artisan optimize:clear
php artisan migrate
```

Updated production frontend assets are included. No Composer dependency changes are required. The fixed `readme.md` is unchanged and is not included in this patch.

## Question Bank and reuse

- Questions now belong to a reusable bank rather than one survey. Existing survey-question links and display order are migrated into the `question_survey` association table; original question IDs and all submitted answers remain unchanged.
- Create a question independently, optionally selecting surveys. Alternatively, create/edit a survey and select the questions it should include from the searchable Question Bank list.
- A question can be linked to multiple surveys without copying it. Removing it from one survey does not remove it from the bank or other surveys.
- Question wording, hints, answer type/options, rating range, required/active flags and display order are shared settings. Editing them changes future forms in linked surveys. Submitted responses retain their original snapshots. Open forms are rejected if the questionnaire has changed.
- Deleting a question removes it from future forms in all surveys through soft deletion. Previous responses remain available. A survey must still have at least one active question before activation.
- The legacy `questions.survey_id` column remains only for schema compatibility; current membership uses the association table. Do not use that legacy column for reporting or new feature code.

## Question form and listing

- Order, Required and Status column headings/cells are centered horizontally and vertically. Survey / Question, Answer Type and Actions retain left alignment.
- Optional **Hints / Information** is shown immediately after the question in the attendance form and is retained with submitted answers.
- Answer type order: **Select, Text, Text Area, Radio Button, Multiple Select, Checkbox, Date Field, Time Field, Rating**.
- Rating minimum/maximum are editable, defaulting to 1 and 5. Bounds must be integers from -1000 through 1000, maximum greater than minimum, with at most 101 choices per scale. Input, server validation, snapshots and reports use the configured range.
- Multiple Select remains a group of checkbox options. The new Checkbox type is one boolean checkbox. A required Checkbox must be checked; an optional unchecked Checkbox is stored as 0 (Unchecked), not as a skipped answer.
- Option fields are displayed for Select/Radio/Multiple Select; rating-bound fields are displayed for Rating. Other types keep the existing validation and date default behavior.

## Expert evaluation data and reports

Administrator can open an Expert/Departmental Expert profile to see its submitted evaluations, counts, question summaries, answer distributions and rating averages.

The module's **Reports** page supports expert, pool type, survey, viva-date range and historical evaluator-role filters. Summary and submission CSV exports include all matching records. The screen paginates submissions; printing covers the currently displayed report page.

- Every response remains associated with its expert, survey, evaluator and viva date.
- Rating means exclude skipped answers and are calculated separately for each expert, question wording/type/options and rating scale. Different scales are not mixed into a misleading overall average.
- Non-rating questions show answered/skipped counts. Option-based questions and checkboxes also show answer distributions; narrative answers remain accessible through View Answers and the submission CSV.
- Multiple-select distribution totals count selected options and can exceed response counts.
- Reports continue to include submissions for soft-deleted experts/surveys. Identity, question, hint and scale snapshots reflect submission time.
- CSV exports include UTF-8 encoding and protect text cells from spreadsheet formula interpretation. Report views/exports are audited.

## Permissions

| Role | Allowed access |
| --- | --- |
| Administrator | All common system management and audit logs; expert, survey and question management; all evaluation answers, expert summaries and reports/exports |
| Staff | Expert Pool Management, survey management and Question Bank management; own account/profile |
| Chairman / Member | Assigned active surveys and their own submitted responses; own account/profile |

Staff cannot access system management, logs, evaluation responses, report pages, report exports or expert evaluation summaries. Menu visibility and direct routes enforce these rules separately from authoring permission.
